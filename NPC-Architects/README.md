# NPC Architects 0.1.5 — experimental source prototype
Forge 1.21.1-52.1.5 / Java 21. No custom client content. Vanilla connection not tested.

## Build
Install Java 21 and obtain the official Forge 1.21.1-52.1.5 MDK from https://files.minecraftforge.net/net/minecraftforge/forge/index_1.21.1.html . Extract its Gradle wrapper (`gradlew`, `gradlew.bat`, `gradle/wrapper/`) into this directory. Use the unmodified MDK wrapper. Run `gradlew.bat build` (Windows) or `./gradlew build` (Linux). Install the generated JAR from `build/libs` on a test Forge server only. The Forge 52 port requires a successful CI build and in-game testing.

## Test
Use an operator on a flat, empty test world. `/architect house 7 7` spawns one builder and creates a house three blocks southeast of your feet. `/architect status`, `/architect pause 1`, `/architect resume 1`, `/architect cancel 1`. Cancel does not undo blocks or despawn the worker. Jobs are saved in the world directory. Keep chunks loaded. A blocked job can be resumed after clearing obstructions or moving the worker. Missing workers do not respawn. Vanilla villager AI may compete with navigation; scaffolding is not implemented and high blocks may stall. No claim integration, line-of-sight enforcement, material consumption, schematic import or custom GUI. Use backups; do not deploy on a production world.

## Diagnostics
`/architect ping` is available to all players; construction and status remain operator level 2. The server log reports initialization, command registration and startup. `pack.mcmeta` covers Minecraft 1.21.1 data (48) and resource (34) pack formats.

## Construction selection
Stand at the first and opposite corner (inclusive) and run /architect pos1 and /architect pos2. Same Y uses height 5; otherwise the inclusive Y span is the height. Width/depth 5–15; height 4–12. /architect rotate 0|90|180|270 changes orientation; selection retains its physical footprint. /architect preview house emits a one-shot particle preview and counts blocked positions; /architect build house starts the job. Direct /architect house 7 7 5 uses a +3 X/Z origin and current rotation. /architect undo [id] pauses and removes only recorded placements still matching the expected block state; it does not restore pre-existing blocks, cannot distinguish identical player replacements, and older jobs lack undo history. Selections reset on restart/dimension change. Undo without an ID targets the latest job globally (operator-only). No scaffolding or claim integration; back up your test world.

## Automatic clearing
New jobs survey the entire rotated rectangular volume, then clear mismatched blocks top-down before building. Matching blueprint blocks remain. Block entities, liquids and unbreakable blocks are rejected; no drops are generated. Clearing uses NPC reach and navigation, no teleportation, no changes outside the footprint. Undo attempts to restore cleared block states if the cell is empty; numeric block-state IDs assume the same registry on restart. Back up the world: ordinary player-built blocks inside the selected volume can be removed; claim protection is not integrated. Existing jobs keep their old progress and do not automatically enter clearing. Preview counts clearing and protected positions.

## Builder protection and recovery
Architect workers are invulnerable and persistent; hostile targeting is canceled for tagged builders. Existing loaded job workers are protected on the next management tick. Confirmed worker death triggers replacement at a safe loaded position when a running job resumes. Missing workers may simply be unloaded, so they are not automatically replaced. For a worker known to be gone, stand near the site and use `/architect recover <id>` as an operator; it preserves clearing and building progress. If the old worker was merely unloaded, a manual replacement can leave an orphan villager. No normal villagers are modified. Protection does not protect nearby players or buildings, and administrative removal can still require recovery. Runtime behavior requires testing.

## Elevated construction controller
Builders no longer use ordinary villager wandering goals. During active clearing/building, controlled movement uses eye-height reach and collision-checked elevated work positions with temporary hovering. If a direct movement route is blocked, the controller may reposition the builder to a verified empty loaded stance near the current target. This is a creative-style fallback, not scaffolding or survival pathfinding. Gravity is restored when paused, blocked, cancelled or finished; builders remain stationary rather than wander. Existing jobs retain their blueprint cursor; use `/architect resume <id>` for blocked jobs. Layer completion and exact blocking reasons are logged. In-game movement still requires verification.
