# MYTHOS Pets 0.1.0
Minecraft 1.21.1 / Forge 52.1.5 / Java 21. Standalone, vanilla clients by design. 21 definitions (18 moved from mounts, 3 added); bat, vex and snow golem locked pending safe controllers. One active pet and independently one active mount. Persistent UUID ownership, exclusive shop/reward acquisition, no wild unlocks, pet riding denied. Commands: /pet list, catalog, shop, buy <id>, summon <id>, dismiss; operator /pet credit <player> <amount>, /pet reward <player> <id> <source>. Separate test wallet, not RPG economy. Owner-initiated combat or hostile attack on owner selects nearby Monster target for 200 ticks; no player targets, allied mobs or marked pets/mounts. Cooldown-based pet-attributed damage, poison, slow, weakness, fire, healing, resistance, speed and luck effects. No actual bleeding, critical strike, armor reduction, damage absorption or scout ability yet. Support effects use vanilla effects and healing; luck is not a custom loot multiplier. AI disabled, invulnerable ephemeral pet, collision-checked follow with repositioning; special vanilla ticks and combat behavior require live testing. No pet progression, GUI, custom animations, shared economy, automated boss rewards or RPG XP attribution yet. No persistent cooldowns across resummon except initial full ability delay. Storage world/mythos-pets.json; atomic synchronous save, fail closed. Mount PR #50 independently removes companion entries; no migration for unreleased development stores. CI and live verification pending.

Players can name any owned pet using `/pet rename <id> <name>` (1–24 characters, spaces allowed), and restore the default with `/pet resetname <id>`. Names persist in the same atomic ownership store, update active nameplates immediately, and never change the pet ID or acquisition restrictions. Duplicate display names are allowed. No formatting codes or control characters.

## 0.2.0
Requires Economy 0.3.0, Merchants 0.3.0 for Pet Merchant purchases. Old pet gold preserved only as inactive legacy data, not converted. Existing unlocked pets and custom names remain valid; purchased pets can be renamed. /pet buy and credit removed. /pet shop lists eligible IDs; prices set per NPC via /merchant pet add cat pet_token 250 5. Premium variants premium_mooncat and premium_sunbird use existing ordinary haste ability and vanilla visuals; no payment integration. Existing locked pets remain locked. Back up economy and pet files together. Live gameplay validation required.

## 0.3.0 — client/server custom pet foundation
Install the same Pets JAR on the dedicated Forge server and every connecting Forge client. Economy remains required on the server only. Standalone singleplayer without Economy is not supported. Mounts and Merchants are unchanged. The existing premium_mooncat ID now summons a registered mythospets:mooncat entity with an original articulated cuboid model, 64x64 texture, head tracking, leg animation and idle tail motion. All other catalog entries keep their original visuals. No ownership schema or prices change. Direct entity spawning is rejected by the authoritative server controller. Existing commands and premium grant restrictions remain unchanged.

Validation before deployment: build CI, dedicated server startup with Economy, client startup without Economy, multiplayer handshake (matching versions and missing Pets rejected), premium grant/summon/rename/dismiss, logout/dimension/death cleanup, unowned summon and direct entity spawn rejection, existing merchant purchases and mount coexistence. Back up world files before deployment. The Mooncat is a foundation model, not a finished high-polygon asset.
